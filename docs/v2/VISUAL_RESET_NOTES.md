# Bounce BTTS 2.0 — Visual Reset

Status: active V2 design direction

## Why this reset exists

The first Phase 2 preview proved the new shell and data wiring, but did not move far enough away from the 1.x visual structure. It remained recognisably card-led and therefore did not meet the intended premium product standard.

The first Phase 3 pass then over-corrected toward an almost entirely dark editorial treatment. That also missed the target: premium Bounce should not read as a black page with oversized serif headings.

## V2 visual target

Bounce 2.0 should feel like **Edinburgh heritage × modern football broadcast × private members club**.

The redesign should be materially different from 1.x at first glance:

- open editorial composition rather than card grids;
- a deliberate mix of deep oxblood / maroon, charcoal, warm stone, off-white and restrained gold rather than an all-dark UI;
- **BOUNCE BTTS LEAGUE** is the unmistakable primary product identity on the Dashboard, with the season displayed dynamically;
- manual swipe/scroll Gameweek navigation remains available rather than reducing Gameweek selection to a dropdown;
- strong but controlled typographic hierarchy: traditional serif for feature/section language, clean modern type for data, navigation and scores;
- subtle St Giles, Heart of Midlothian mosaic, Edinburgh skyline and Tynecastle details;
- full-width visual bands and ruled ledgers instead of repeated rounded containers;
- cards reserved for genuine emphasis or exceptional states;
- calm, fast interaction and mobile-first scanability;
- premium does not mean decorative overload: imagery is atmospheric and hierarchy remains functional.

## Core pages establishing the language

### Dashboard

The Dashboard is the front door of the product. **BOUNCE BTTS LEAGUE** must be front and centre before the current Gameweek status. Current action, selection, league pulse, everyone's picks and standing then flow beneath it as composed surfaces rather than a stack of widgets.

### Stat Centre

A data-room / sports editorial destination. It is structured into **League**, **Players**, **Form & Trends**, and **Records** rather than presenting a flat collection of stat cards. Statistics should tell a story and support drill-down. Warm stone/off-white surfaces should provide contrast to selected oxblood and charcoal data bands.

### Admin

A league control centre. It presents real system state, the current gameweek, submissions, fixture coverage and attention items first. Routine operations are separated from advanced intervention and recovery tooling. It shares the same stone/oxblood/charcoal system rather than becoming a separate dark admin theme.

## Phase 3 acceptance

Phase 3 is accepted only when Dashboard, Stat Centre and Admin are visibly and structurally different from 1.x, the dominant page language is editorial bands/ledgers/typography rather than rounded cards, canonical league behaviour remains untouched, iPhone/iPad layouts remain clean, the Dashboard visibly identifies the product, Gameweeks remain manually scrollable, and the same visual language can be inherited by every remaining V2 section.

## Review test

A V2 screenshot should not plausibly be mistaken for the 1.x interface. It should also not look like a generic dark editorial template. The Bounce identity, Edinburgh character and premium sports-product hierarchy should be obvious without becoming decorative or busy.

This direction applies to every later V2 surface so the final product remains stylistically consistent.
